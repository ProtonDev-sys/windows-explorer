# Architecture

`WindowsExplorer.exe` is a Unicode, x64, C++20 Win32 process. The manifest declares per-monitor DPI awareness, long-path awareness, common-controls version 6, and `asInvoker` privileges. The MSVC runtime is linked statically. Windows supplies the Shell, common controls, property system, COM, and archive utility.

## Native host

`ExplorerApp` owns the window, native command controls, address/search edits, breadcrumbs, status bar, and `IExplorerBrowser`. It implements service discovery, browser events, pane visibility, common-dialog browser callbacks, and folder filtering. Browser initialization failures and window destruction detach the event subscription, filter, and site before releasing COM references.

The Shell owns folder enumeration, presentation, native menus, thumbnails, and namespace providers. This allows the application to work with virtual locations and existing extensions without implementing a second filesystem-only view. Behavior varies by installed Windows components; Shell reuse does not establish complete Explorer.exe feature parity. Microsoft's [ExplorerBrowser documentation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-iexplorerbrowser) describes this hosting model.

Navigation history stores absolute PIDLs, not filesystem path strings. History commits only when the completed PIDL matches the requested destination. Direct navigation discards a pending history request, and new navigation truncates the forward branch. Pane changes rebuild the native browser while retaining the host's history.

`IFolderView2` controls the eight layouts, sort/group properties, selection, and checkboxes. `IColumnManager` supplies the Add columns menu, visible-column changes, and autosizing; the Name column stays visible. Preview and Details are mutually exclusive. Hidden files use the app's filter; hidden system files remain excluded. File extensions use the shared Windows Shell setting only after an explicit user command.

The command band has Home, Share, View, Computer, and contextual Search or Library pages. Supported saved-search metadata can restore the Search page after reopening. A native client-area toolbar exposes a bounded catalog of commands with add/remove, order, reset, and above/below placement; stable command tokens and placement persist in app-owned settings. Its four model/persistence groups and five hidden-control checks passed, including the permanent-delete selection guard. It does not implement Explorer's full Ribbon Framework markup, caption/title-bar toolbar placement, or other contextual pages. Minimum window width is 1,030 DPI-scaled pixels; the hidden View-band bounds check passed at 96 DPI. Visual appearance and other DPI configurations remain unverified. [Native toolbar controls](https://learn.microsoft.com/en-us/windows/win32/controls/toolbar-controls), [Ribbon QAT docking baseline](https://learn.microsoft.com/en-us/windows/win32/api/uiribbon/ne-uiribbon-ui_controldock)

F6/Shift+F6 use a pure availability-aware model for Address, Search, Folder view, Command band, and Navigation. The host maps those regions to Win32 focus or native `IShellView::UIActivate`; tests verify the model, not actual focus activation or accessibility. F11 stores window style/placement and uses the nearest monitor rectangle. Hidden tests restore style and geometry without showing the window; maximized-window placement restoration is not established by that path.

## Operations

`ShellOperations` uses [IFileOperation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ifileoperation) on the UI's STA for native file-operation semantics. It checks per-item results and aborted status. Normal user operations retain native progress/conflict dialogs; silent fixture operations disable UI and do not add undo records. Delete requests recycling; permanent deletion is a separate confirmed command. No public undo-stack execution interface is assumed.

Copy/cut publish native `IDataObject` objects with preferred drop effects. Paste interprets the clipboard through the Shell, then reports optimized-move feedback. Shutdown flushes only clipboard data owned by the application before its COM apartment ends.

`ItemActions` formats quoted paths and resolves filesystem paths with a canonical Shell-name fallback for virtual items. Its hide/unhide operation preflights the selection, changes only the Hidden attribute of selected items, and does not recurse into folders. Tests verify unrelated compressed/sparse attributes remain intact and reject a real junction without touching its target or earlier selected files. Clipboard publication remains outside the tests.

`ExtraOperations` uses `IShellLinkW`/`IPersistFile` for `.lnk` files. ZIP work runs on a background task. The native wide-path code stages inputs because Windows 10's bundled tar has limitations with Unicode archive and directory arguments. Tar receives ASCII relative paths and `CREATE_NO_WINDOW`; no command shell is involved. Validation rejects unsafe or unsupported ZIP structures, and final output is published without replacing an existing destination. Staging consumes additional disk space; closing during archive work can wait for the worker to finish.

`NativeContextMenu` owns Shell menu/site references for one STA interaction, preserves command ID ranges, and forwards delayed/owner-drawn messages through `IContextMenu2/3`. The registered New menu uses `CLSID_NewMenu`, installed ShellNew handlers, and the current native view as its site. Its destination must be an actual filesystem directory; the Shell's folder attribute alone does not admit a ZIP file. Six groups/91 assertions verify real hidden fixture menu enumeration and ZIP destination rejection; invocation, stale/disabled ID rejection, message handling, and lifetime tests use mock handlers. Tests never display a popup or execute installed New handlers. [Registered ShellNew handlers](https://learn.microsoft.com/en-us/windows/win32/shell/context), [Context-menu command ranges](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icontextmenu-querycontextmenu), [Menu-message forwarding](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icontextmenu3-handlemenumsg2)

The host caches actual filesystem-directory status after navigation and revalidates it before New folder/text/shortcut and terminal commands. ZIP namespace folders disable those destinations and the registered New menu. Paste remains governed by the separate native Shell capability.

`NativeShare` uses `IDataTransferManagerInterop` for the owning HWND, separate from Sharing property pages. Bounded planning accepts up to 256 existing filesystem files and rejects physical directories, virtual items, duplicate/device/ADS paths, and reparse points. Regular ZIP files are eligible even when the Shell exposes their folder attribute. A deferred `DataPackage` provider resolves actual `StorageFile` items asynchronously, observes the provider deadline, and retains shared lifetime/cancellation state independently of the app object. The host removes event registrations before destroying its HWND. C++/WinRT calls use Windows' runtime, without a web runtime. Five headless groups verify real payload resolution, ZIP acceptance, Unicode paths, failure HRESULTs, STA ownership, and cleanup; hidden host checks verify directory rejection and ZIP selection eligibility. Picker display and recipient delivery remain untested. [Desktop Share interop](https://learn.microsoft.com/en-us/windows/apps/develop/ui/display-ui-objects), [Deferred providers](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.datatransfer.datapackage.setdataprovider)

`ShellLibrary` wraps the OS `IShellLibrary` implementation for load, included folders, default save folder, content template, Commit, and new `.library-ms` files. Save requires an explicit destination and `LSF_FAILIFTHERE`; the helper never chooses the user's Libraries folder implicitly. Its Save writer is released before navigation/reloading. Normal UI commands use destination/folder pickers and disable mutations for read-only libraries; headless mode prohibits them. The included/default location comparison uses canonical identity with filesystem-path fallback, and path inputs are made fully qualified before Shell parsing. Three integrated native groups passed; hidden host checks verify context creation, included/default location metadata, and context removal after navigation. Aggregation rendering and provider behavior remain unverified. [IShellLibrary](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ishelllibrary), [Save](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllibrary-save), [Commit](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllibrary-commit)

## Search and responsiveness

Search parses AQS with `IQueryParserManager`, resolves dates and virtual properties, and creates an `ISearchFolderItemFactory` result with an explicit scope. It navigates the native result object directly, following Microsoft's [ExplorerBrowserSearch sample](https://learn.microsoft.com/en-us/windows/win32/shell/samples-explorerbrowsersearch). A filesystem-only shallow search adds an `IConditionFactory` equality condition on canonical `System.ItemFolderPathDisplay`; query text cannot broaden that scope. Null recursive scope selects This PC. A bounded unresolved-condition-tree guard rejects explicit `COP_WORD_STARTSWITH` on `System.FileName` before native execution; it allows literal `$<` text, other properties, default terms, starts-with, and wildcard operations.

Each in-session search record associates its result PIDL with origin PIDL, base query, recursion, and three refinement categories. Active state commits when navigation to that result completes. Failed navigation preserves the committed search; another filter in the same category replaces its predecessor. Close search returns to the origin. Recent searches retain up to 20 unique query strings in memory for the current session.

`saveSearch` serializes the unresolved condition tree into the [documented `.search-ms` XML format](https://learn.microsoft.com/en-us/windows/win32/search/-search-savedsearchfileformat), leaving relative-date expressions relative. It escapes XML attributes, writes UTF-8, and uses exclusive file creation. Filesystem folders and This PC are supported; unspecified-property generic terms, shallow virtual scopes, arbitrary virtual saved scopes, literal-percent paths, unverified explicit word-prefix operators, and unsupported unresolved value types are rejected before writing. Generic leaves depend on parser input metadata to choose their matching property/operator; persisting them as plain XML was not faithful. Native fixture tests verify explicit-property reopening, updated results, scope, operators, relative dates, and generic rejection without a created file.

`readSavedSearch` reads a stable file-handle snapshot of at most 1 MiB into MSXML6, disables DTD/external resources and inline schemas, and bounds XML depth/nodes and AQS length. It reconstructs a documented condition subset with `IConditionFactory2`, restates leaves with `IQueryParser::RestateToString(..., FALSE)`, and uses documented canonical literal quoting where native reconstruction loses it. Native resolved property/operator/scalar trees and unresolved relative-date tokens must match after reparsing before metadata is returned. Output remains unchanged on failure. The single supported known-folder GUID is matched directly, without ProgID conversion or registry mutation. Supported files contain one filesystem include or recursive This PC, `kindList=item`, and supported wstr/string condition/schema types; multiple/excluded scopes, internal/provider elements, Blurb/unknown types, and other unsupported formats reject. Thirty-five native query fixtures verify live/saved/restored result parity, with known exact identities for the main filename cases. [Restatement](https://learn.microsoft.com/en-us/windows/win32/api/structuredquery/nf-structuredquery-iqueryparser-restatetostring), [Canonical AQS](https://learn.microsoft.com/en-us/windows/win32/search/-search-3x-advancedquerysyntax), [MSXML safety settings](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms766391(v=vs.85))

Search background policy follows in-session result PIDLs and reopened native saved searches identified by [`System.ItemType`](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-itemtype), rather than a filename suffix. A directory named with `.search-ms` remains ordinary. After successful native navigation, supported saved metadata restores query, origin scope, recursion, and contextual controls; its condition becomes the base query with no inferred category state. Unsupported saved formats still navigate through the Shell with background policy, without editable host search metadata. Open file location requires one filesystem-backed result, resolves its real filesystem parent rather than the search container, and retries selecting the exact child after parent navigation; that selection path has a hidden fixture check.

The host returns `CDB2GVF_NOINCLUDEITEM` for search views to avoid the documented compatibility path that filters searches on the UI thread. Ordinary folders use a lightweight attribute filter for app-local hidden-item state. Startup defaults to This PC. The status bar reports view counts and navigation timing; it does not repeatedly invoke selected-item property handlers or recursively total folder sizes.

This design removes the need for an additional web runtime and avoids some unnecessary work. Shell extensions, network providers, thumbnail handlers, synchronous namespace parsing, and Shell-owned operations can still block. A 1,000-file fixture verifies basic behavior and records timing; it is not a comparison with Explorer.exe. Provider isolation, cancellable archive jobs, metadata workers, and broader performance measurements remain future work.

## Tests

The integrated console suite checks core/settings logic, keyboard/focus models, native search results and saved metadata, Share payloads, native menu enumeration/mock invocation, toolbar state, libraries, item actions, and silent operations on owned fixtures. The hidden-window host initializes real native controls and Shell views, pumps messages, reads back state, and observes process-owned visible windows. Headless browsers set `EBO_NOPERSISTVIEWSTATE`; its native flag readback passed. The warning-free local Release build passed CTest 2/2 and an independent hidden-host run passed 72/72 checks. Tests never display the app, invoke interactive handlers/share recipients, take visible screenshots, or automate the desktop. [Hosted CI](https://github.com/ProtonDev-sys/windows-explorer/actions/runs/37169510842) passed the expanded `ce231210` source with CTest 2/2 and 72/72 host checks on Windows Server 2022; local validation uses Windows 10.
