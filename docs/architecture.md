# Architecture

`WindowsExplorer.exe` is a Unicode x64 C++20 Win32 application. Its manifest declares per-monitor DPI awareness, long-path awareness, common-controls version 6 and `asInvoker` privileges. MSVC links the C++ runtime statically. Windows supplies the Shell view, Ribbon Framework, property system, namespace providers and installed command handlers. There is no web runtime.

## Native window and namespaces

`ExplorerApp` is heap-owned with real atomic COM AddRef/Release lifetime. It owns the top-level HWND, native Ribbon host, navigation/address/search controls and `IExplorerBrowser`, and implements events, service discovery, pane visibility, common-dialog callbacks and folder filtering. Shutdown cancels tasks, detaches the actual view/browser sites and events, revokes drop registrations and releases native references during owner teardown. The Shell owns item enumeration/presentation, thumbnails, menus, footer and namespace extensions. Provider reuse preserves available native behavior; it does not prove complete Explorer.exe parity. [ExplorerBrowser](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-iexplorerbrowser)

Navigation history stores absolute PIDLs. History commits only when the completed destination matches its pending request; failed navigation preserves the previous destination, and new navigation truncates the forward branch. The normal browser uses the `WindowsExplorer.Native` property bag and reads the actual restored layout rather than forcing one global mode on every folder. Headless browsers set `EBO_NOPERSISTVIEWSTATE` and initialize a deterministic fixture layout. Default startup follows read-only Windows `LaunchTo`, with Quick access as the default; an explicit app startup preference takes precedence.

Normal `ReadCabinetState` policy controls available full-path captions and single-folder default activation in a new app window. Setting-change refresh reads policy without writing it. Explicit breadcrumb/history/search navigation remains in the current app window; nonfolder/modifier-specific default commands retain the native provider path. Headless policy remains isolated. [CABINETSTATE](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ns-shlobj_core-cabinetstate)

`IFolderView2` supplies eight modes/icon sizes, selection, grouping and sorting. Full Sort, Group and Add columns cascades come from the actual view providers; `IColumnManager` supplies native column identities/order/visibility and autosizing. Preview and Details are mutually exclusive. Normal hidden/protected/extension state comes from cached read-only shared Shell policy, refreshed on relevant setting changes. Explicit commands use native settings behavior. Headless fixtures use isolated policy and never write user settings. The actual Shell frame owns the visible footer and its view shortcuts; the unused duplicate host controls and their redundant property reads have been removed.

Normal startup uses public `IUIFramework::LoadUI` with the installed `ExplorerFrame.dll` `EXPLORER_RIBBON` resource and an adapter from its native command identities to actual app/provider routes. The separately compiled authored Ribbon supports fallback and deterministic headless comparison. Both cover Home, Share, View, Computer and Network pages plus Picture, Drive, Compressed, Search, Library, Recycle Bin, Application, Shortcut, Music, Video and Disc Image contexts. QAT customization/docking, caption integration, keytips and minimized state use real Framework properties and collections. Close-time native readback persists settings for reopening. Initialized registered handlers supply localized titles/tooltips/icon specifications before registry fallbacks. OS revision/language can change these resources, so a current native resource does not automatically match every historical screenshot. [Public Ribbon loading](https://learn.microsoft.com/en-us/windows/win32/api/uiribbon/nf-uiribbon-iuiframework-loadui), [QAT docking](https://learn.microsoft.com/en-us/windows/win32/api/uiribbon/ne-uiribbon-ui_controldock)

Breadcrumbs retain the full native Desktop-to-current ancestor chain independently of width-driven toolbar slots. A hidden-ancestor menu keeps every omitted node available in root-to-leaf order; its targets are cloned before the modal menu and rejected after a navigation generation changes. The Desktop root remains a distinct native target, and each ordinary child dropdown uses the original adjacent child even when that child is hidden. Ampersands are escaped in native menu labels. Owned deep Unicode fixtures compare the model with independent `IShellItem::GetParent` traversal, real HMENU targets/labels, narrow/wide toolbar geometry and actual folder FileIDs. These are behavior checks; exact stock overflow-menu appearance remains a separate comparison boundary.

Folders are enumerated only when requested. `EnumObjects(nullptr, SHCONTF_FOLDERS)` avoids credential/media prompts, `SHCreateItemWithParent` retains virtual children, and native `CompareIDs` defines order. Entry/time/serialized-size limits report incomplete snapshots with stop reasons. The worker transfers PIDL bytes/labels and owns its STA and creator-desktop handle; polling materializes returned Shell items on the owner STA. Cancellation never waits for a blocked provider. Final shutdown drains workers while the owning apartment remains initialized. Breadcrumb OLE routing binds the actual destination `IDropTarget`, retains the original `IDataObject` and preserves modifiers/effects/site lifetime. Tests use fake Drop providers. [EnumObjects](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellfolder-enumobjects), [BindToHandler](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitem-bindtohandler)

Navigation-pane options use the actual tree service: pinned/show-all style, Libraries root add/remove and deferred root-to-leaf expansion of canonical Shell ancestors. Ctrl+Shift+E expands the current ancestors once without changing the persistent option. The embedded Windows tree can return success while declining asynchronous expansion of large folders. `expandNativeTreeItem` maps the real native item rectangle from screen to its control's client coordinates, validates the canonical NSTC hit and actual owned TreeView row, and sends public `TVM_EXPAND` to that exact row. It inserts no substitute root, changes no focus/selection and waits through the host's existing timer. Bounds, owner process/thread, disabled/native state and readback failures remain explicit. Owned translated-pane/102-child fixtures and the full app's deep current-folder native bounds verify this path. [TVM_EXPAND](https://learn.microsoft.com/en-us/windows/win32/controls/tvm-expand)

Expansion tasks are bounded and invalidated by navigation. The Windows 10 F6/Shift+F6 ring is content, Details sorting buttons, native status view buttons, navigation/address/search toolbar, and navigation tree. Alt retains Ribbon navigation; Alt+D/Ctrl+L and Ctrl+E retain direct address/search access. The actual Shell frame owns its visible footer. Its status radios and Details split buttons receive only `IAccessible::accSelect(SELFLAG_TAKEFOCUS)` after native role, geometry, visibility and HWND ownership checks; successful focus requires the provider's focused-state readback. Discovery stops outside file/tree item lists. Toolbar Tab/Shift+Tab visits actual enabled visible buttons and edits, and Enter uses the existing command guards. F11 retains style/placement and uses the nearest monitor. Full accessibility, RTL and mixed-monitor equivalence require separate evidence. [Windows 10 screen-reader navigation](https://support.microsoft.com/en-us/accessibility/windows/use-a-screen-reader-to-explore-and-navigate-file-explorer-in-windows), [public accessible focus](https://learn.microsoft.com/en-us/windows/win32/api/oleacc/nf-oleacc-iaccessible-accselect)

## Command state and invocation

`app_commands` maps host/Ribbon IDs to host operations, contextual namespace actions or exact installed `Windows.*` keys and target scope. Semantic requirements exclude unrelated namespaces before queries. A registered key alone does not establish applicability. Native disabled/hidden/checked state, absent components, failures and `E_PENDING` remain distinct.

Provider-backed host collections also query their exact registered state; a Host route does not imply an enabled native New-menu root. Documented app-owned copy/cut/rename/properties/pane/window/help controls retain their actual host/SFGAO authority when their presentation key has no public state interface. The separate saved-query writer, app history and `IShellLibrary` folder chooser use their own capability contracts. They are not disabled by a different selected-item action that shares their artwork.

Fast state instantiates the literal registered `ExplorerCommandHandler` or `CommandStateHandler`, initializes the exact name with a read-only `IPropertyBag` when supported, and attaches the actual view site through `IObjectWithSite`. `GetState(FALSE)` builds no full menu. Selection commands receive actual targets; background Explorer commands receive null selection and state-only handlers receive their documented current-folder array. Sites detach before provider release. [IInitializeCommand](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iinitializecommand-initialize), [Explorer command state](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iexplorercommand-getstate), [State-only handler](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iexplorercommandstate-getstate)

Pending registered states complete through `GetState(TRUE)` on another STA. The standard Global Interface Table marshals selection/site interfaces; no raw foreign-apartment pointer is called. Before launch, the worker lease retains an independently owned duplicate of the exact creator desktop without switch rights. The worker attaches to the creator's borrowed `GetThreadDesktop` connection before COM/provider calls; the duplicate is never attached. **The creator must keep that exact connection, its apartment and its sites alive through the final worker drain.** Restoring or closing the creator desktop, or exiting its STA after cancellation alone, violates this precondition. Borrowed desktop handles are never closed. [GIT](https://learn.microsoft.com/en-us/windows/win32/com/creating-the-global-interface-table), [Borrowed desktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getthreaddesktop), [Desktop attachment](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddesktop)

Workers release providers and COM before finishing their lease. An owned synchronization handle and a windowless `RegisterWaitForSingleObject` callback retain the duplicate and worker group until actual kernel-thread termination. That callback makes no USER32/COM calls: it queues the unused duplicate for closure on the creator STA during a bounded `CoWaitForMultipleHandles` drain. Groups belong to the creator thread lifetime rather than a recyclable thread ID. The drain establishes termination of the app's workers and closure of its keepalive duplicates; it does not establish termination of native Shell helper threads. Native helpers can inherit the creator's borrowed desktop connection and outlive a worker. Their windows and connections are never forcibly destroyed or reassigned; a private desktop whose original handle remains busy is retained safely until native/process cleanup. [Thread-exit wait](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-registerwaitforsingleobject), [Desktop closure](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-closedesktop), [STA drain](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-cowaitformultiplehandles)

Polling is nonblocking, navigation/selection/clipboard changes cancel registrations, and stale results are discarded. Concurrency is bounded; busy starts retry. Revoking a GIT registration prevents future lookup, but an already-resolved proxy can retain its COM object until release. Native sites detach during teardown and the host's real reference count prevents stack-object lifetime assumptions. Owned-STA fixtures verify site retention after owner release, cancellation/output preservation and exactly one destruction. The separate worker-lease fixture exercises a real marshaled creator-STA callback, a visible window only on a private desktop, exact borrowed-connection identity and the final zero-pending drain. A call already blocked inside a provider cannot be forcibly interrupted; shutdown retains a timeout as a failure.

Static association states have a separate full-selection native-menu worker. A known ordinary single-item association supplies only a negative prefilter; positive, multiple, shortcut and unknown custom-namespace selections remain pending until native menu truth, including its `MultiSelectModel` and policy. A shortcut's association array can omit a real verb supplied by its target, so it cannot reject that native leaf. The worker reads the original data object's `CFSTR_SHELLIDLIST`, validates the CIDA count, offsets and every terminated PIDL, and creates a worker-local native array from all original identities in their original order. When the provider does not support CIDA, the correctly marshaled original full array remains authoritative, including non-agile custom providers. Virtual identities remain PIDLs; no path or first-item substitution is used. The actual marshaled view site attaches before `QueryContextMenu`. Only an exact unique canonical leaf supplies state; absent, ambiguous, submenu, failed and cancelled results preserve failure output. Contextual aliases share one complete menu and retain the actual matching canonical verb. A dedicated read-only `createLeafState` omits `CMF_SYNCCASCADEMENU`, preserves other query flags and rejects invocation, delayed population and menu-message forwarding. Normal popup/invocation menus retain synchronous cascades. Direct native 1/2/16/5,001/10,000-item all-file and final-folder selections compare root-leaf ambiguity/disabled/checked state; registered Remove properties is checked separately. Omitting the cascade flag preserved that truth but did not materially shorten the tested large native menu query. The worker never invokes a verb or publishes clipboard data. A non-agile mock verifies complete 100,001-item states, aliases and cancellation. Creator STA waits must pump COM messages, including in headless fixtures. [Shell identity data](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard), [Native query flags](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icontextmenu-querycontextmenu), [COM apartment message dispatch](https://learn.microsoft.com/en-us/windows/win32/com/processes--threads--and-apartments)

A state-only worker requests `DFMR_NO_RESOURCE_VERBS` through the actual `IDefaultFolderMenuInitialize` only when every requested canonical leaf excludes built-in cut/copy/paste/link/delete/rename/properties and their registered aliases. This retains static associations and all dynamic native handlers; it does not request `DFMR_STATIC_VERBS_ONLY` or replace selection-menu truth with generic CommandStore wrapper state. Existing documented restrictions are preserved, and the original view site attaches before the restriction is set. After every attempted restricted query, the original restrictions are restored before canonical readback; query failure takes precedence over a restoration failure, which otherwise remains a native error. Retained-provider followups must expose the original complete normal menu. An unsupported interface keeps the unrestricted query; a supported getter/setter failure retains its native HRESULT and unchanged capability output. Normal menus and invocation keep their complete preparation. Verification compares non-resource leaf presence, multiplicity, disabled and checked state against fresh complete menus on native 1/2/16/5,001/10,000-item all-file and final-folder selections, executes catalog static aliases on real full-CIDA workers, and checks resource-request bypass, custom providers, shortcut redirection, failure and isolation contracts. [Native menu restrictions](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-default_folder_menu_restrictions), [Restriction setter](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-idefaultfoldermenuinitialize-setmenurestrictions)
Capabilities are cached once per namespace/selection/provider change; Ribbon callbacks consume the cache. Each query explicitly marks an actual default-selection-menu fallback. Compatible pending static commands and contextual alias groups share one worker, one complete selection snapshot and one actual native menu per generation. Every canonical leaf retains its independent missing, ambiguous, checked, disabled or failed result; alias reduction follows the existing first-enabled/disabled/error precedence. Registered-only Remove properties, redirected compatibility links, background providers and the separate archive target remain distinct. A global preparation failure or cancellation publishes no partial batch. Owned non-agile 100,001-item mocks verify one native menu query, tail/checked state and cancellation; actual all-file/mixed 5,001-item batches match the fresh original native menu. Owner-thread full menus load on explicit popup/invocation; static state menus run on the separate worker. `NativeContextMenu` preserves ordinals, disabled ancestors and delayed/owner-drawn messages through `IContextMenu2/3`. Borrowed submenus carry a generation and must not be destroyed/reparented or used after reset; WndProc forwards provider messages. Retained galleries hold the actual enumerated child commands, original selection and site, including nested children. `invokePath` revalidates every retained native ancestor and leaf; an MRU destination is never reconstructed from a translated label or later index. Root state initializes the same provider instance before enumeration; a Library cascade additionally needs an enabled actual Library context. Failed/pending/disabled child providers are not forced to enumerate. Disabled Extract-to may expose read-only destinations, but cannot invoke them. [Menu ranges](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icontextmenu-querycontextmenu), [Forwarding](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icontextmenu3-handlemenumsg)

Read-only task timings separate data-object export, full PIDL reconstruction, context binding, native menu query, leaf enumeration, state reduction and total worker time. State reduction includes explicit menu detachment on successful paths; provider/COM/lease teardown appears in the remaining total. Timing output is separate from capability output: a completed failed native query can expose timings without becoming enabled, and pending/cancelled calls preserve the caller's output. Distribution and comparison claims require an isolated timing run and belong in the performance report.

Default-selection native menu work and synchronous view-selection invocation share one process-wide reservation. The selection facade validates the exact owner STA, view identity and canonical command before reserving it; a busy generation uses the documented bulk operation on that same folder view. A pumped invocation retains both its handler and the host interaction guard through provider/site detachment, so reentrant refresh cannot destroy the active menu. Cancelling or destroying a task cannot release it while a native query is blocked. The worker releases this work reservation only after native references and COM are released and its lease is finished; another generation then retries through `ERROR_BUSY`. The separate desktop lease still waits for kernel-thread termination. Registered-only menus and registered/background state providers retain their separate bounded worker capacity. A blocked-provider fixture proves cancellation stays nonblocking, single/alias/batch replacements remain busy without constructing another menu, registered-only work stays independent and the latest complete 100,001-item batch succeeds after actual cleanup.

Media contexts read the full array's `PKEY_Kind` using `GPS_FASTPROPERTIESONLY | GPS_BESTEFFORT`. Multi-valued strings aggregate by intersection: one non-media item removes an all-Music context. There is no 256-item context limit or per-item content read. Actual 257-file/mixed fixtures verify this. [Array aggregation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemarray-getpropertystore), [Fast property flags](https://learn.microsoft.com/en-us/windows/win32/api/propsys/ne-propsys-getpropertystoreflags)

Namespace initialization retains the full native selection/count/site without a 100,000-item rejection. Native filesystem/folder/link facts use `GetAttributes(AND | ALLITEMS)`. The default native AND query missed the final file in an actual 100,001-item array; the documented ALLITEMS flag produces complete semantic eligibility. Three real arrays made from repeated owned folder/shortcut identities plus a final file or static virtual identity prove the counterexamples without creating 100,000 files. A mock array also verifies zero eager per-item reads, exact native context/site retention and unchanged headless invocation guards. [Complete attribute aggregation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemarray-getattributes)

Optional physical/UNC/type details inspect every original target up to a 100,000-item budget. Larger selections expose `detailedTargetsKnown=false`, retain native attributes and can query actual registered full-selection providers or plan their exact enabled native menu leaves. Unknown optional facts cannot enable SendTo email/fax, public Offline Files pinning or a guessed Cast association fallback. Image/media/cast candidates narrow monotonically during detailed inspection, so subsequent targets skip perceived-type/property-store work after all candidates are false. `.lnk` alone never establishes Application Tools. Fast stored target flags reject folders, including executable-looking folder names. If a resident local shortcut's fast target path is unavailable, a bounded no-recall, non-reparse file snapshot is loaded through public `IPersistStream` and `IShellLink::GetPath(SLGP_RAWPATH)`. Offline/cloud/UNC shortcuts are excluded from that fallback. It never resolves the shortcut, accesses its target, expands target environments or executes it. [Stored raw path](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getpath)

## Search and persistence

Search uses localized `IQueryParserManager`/`ICondition` and `ISearchFolderItemFactory`, navigating the real result object. Native arrays provide union scopes; libraries expand to included folders. Shallow filesystem queries intersect canonical ItemFolderPathDisplay restrictions so query text cannot broaden scope. Relative dates/virtual properties resolve for execution. Explicit filename word-prefix conditions have exact native live/saved/import/re-save identity coverage, including negation and multiword values; literal `$<` text/default terms and other supported operators work. [ExplorerBrowserSearch](https://learn.microsoft.com/en-us/windows/win32/shell/samples-explorerbrowsersearch)

Completed matching navigation commits origin PIDL, base query, recursion, actual scope array and replacement refinements. Failure preserves committed search; Close returns to origin; Search again reruns over This PC. Policy-aware recent-query history persists in app-owned storage and drives native `IAutoComplete`. Logs do not publish private query/history text.

Search contexts and presentation snapshots retain the original factory PIDL together with the actual completed-view and travel-history aliases: canonically equal native search objects can have different serialized identities. Shared pruning keeps the newest metadata for duplicate identities, preserves current/history locations and the fixed pending/origin/destination targets, and removes the oldest unpinned entries above 100. Fully pinned entries are bounded by the 100-entry travel history, seven fixed targets and newest entry. Size and hash shortlist serialized comparisons; full-byte comparison prevents hash collisions from merging identities. Pruning performs no Shell provider comparisons. Owned headless checks exercise 120 genuine native factory identities, differing factory/completed bytes with canonical equality, scope rules, file properties, Content32 presentation and actual Back restoration.

Contents/System/Compressed options use actual registered handlers and public `GetState` checkbox authority. The public factory has no option setters. Disposable-VM fixtures establish native transitions and fresh-factory result equality for content-only files/ZIP members, with exact settings restoration. Host Boolean fields or internal XML/provider flags do not replace native policy. [Verified semantics](search-options-verification.md)

The documented `.search-ms` writer retains unresolved relative dates and resolves generic leaves with original parser context. UTF-8/XML escaping, scalar canonicalization, exclusive creation and cleanup preserve text/no-overwrite behavior. Union filesystem locations/library expansion are supported. `SearchScopeRule` retains each location's include/exclude and recursion semantics; four owned fixtures verify mixed recursion, recursive child/deep exclusions and overlapping roots. Five kind fixtures preserve actual typed native values and loader behavior, including duplicate and item-sentinel cases. The bounded reader snapshots a stable handle into MSXML6 with DTD/external resources/inline schemas disabled. Native resolved fingerprints and unresolved relative-date tokens must survive restatement/reparse. Output is unchanged on failure, including scope arrays/rules; supported scopes survive refinement. Supported physical shallow exclusions, exclusions equal to an included root and excluded direct children of shallow includes use an exact protective path predicate because the unindexed provider's scope XML alone produced incorrect membership. Editable import requires that complete matching outer predicate and reconstructs it for live and saved searches; unguarded or altered external queries stay native-view-only. Repeated all-item sentinels and unsupported virtual combinations remain native-view-only. Native browsing of unsupported files does not establish editable metadata. [Public format](https://learn.microsoft.com/en-us/windows/win32/search/-search-savedsearchfileformat), [Persistence evidence](saved-search-verification.md)

Search identification follows real result PIDLs/native ItemType; a physical `.search-ms` directory stays ordinary. Normal Open file location retains the complete native selected-result array and actual view site. The registered SearchOpenLocation composite lacks a public initializer on the tested Windows version; its exact bounded read-only VerbList delegates state to the two installed leaf handlers. Failed/pending leaves preserve failure output and take precedence over a successful sibling. Invocation uses the actual registered parent menu ordinal. Owned zero/one/two-same-parent/three-mixed-result and static virtual-target probes match native availability; they do not imply every virtual provider enables the command. The one-file owned headless navigation simulation remains separate. Native OpenSearchViewSite supplies its conditional Search-again leaf. Search views return `CDB2GVF_NOINCLUDEITEM` to avoid the documented UI-thread filter compatibility path; ordinary folders use lightweight policy filtering.

## Performance, themes and evidence

Cached state, asynchronous pending completion, lazy menus/breadcrumbs and fast classification avoid eager work. Native parsing/extensions/network providers can still block.
