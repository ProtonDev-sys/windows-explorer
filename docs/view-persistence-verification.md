# Native folder-view persistence

The normal application uses `IExplorerBrowser::SetPropertyBag(L"WindowsExplorer.Native")` and initializes the view with `FVM_AUTO`. The named bag separates application-specific view state. Microsoft documents automatic saving when a current view is destroyed, navigation begins, or the browser is destroyed, if the view has been modified. A fresh location falls back to the location's existing state or its file-type template. These are native Shell semantics, rather than an application configuration file. [SetPropertyBag contract](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iexplorerbrowser-setpropertybag).

`ReadCabinetState` supplies the user's native policy. Its FALSE return means that the output contains defaults, not that the output is invalid. `CABINETSTATE::fSaveLocalView` selects remembering individual folders versus global settings. The app adds `EBO_NOPERSISTVIEWSTATE` when that policy disables local saving, and always adds it for ordinary headless tests. No cabinet setting is written. [ReadCabinetState](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-readcabinetstate), [CABINETSTATE](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ns-shlobj_core-cabinetstate), [browser options](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-explorer_browser_options).

The Shell stores these settings in its per-user view-state store. A private desktop isolates windows; it does not isolate that store. The new `tests/native_view_persistence_tests.cpp` consequently checks **both** `GITHUB_ACTIONS=true` and `WINDOWSEXPLORER_VIEW_PERSISTENCE_TEST=1` before COM, desktop creation, windows or files. It must run only on a genuine disposable hosted runner. Local invocation returns SKIP. There is no registry redirection, invented environment, manual Bag write or cleanup of user registry entries.

The fixture creates two fresh owned GUID-scoped folders and eight deterministic files in each. It uses the production bag name, production frame/travel/border options, `FVM_AUTO` and actual `IExplorerBrowser`/`IFolderView2`/`IColumnManager` objects on an owned private desktop. To realize native item membership, only the exact owned frame is briefly shown and activated on that noninteractive desktop, then hidden before view-state inspection. Ownership, desktop isolation and input-desktop visibility are checked during this phase; other visible windows remain failures. The test applies different view modes/icon sizes, two-key sort orders, grouping keys/directions, visible column orders and widths. It reads each applied value from the native view and requires the requested values before using that snapshot as the restoration expectation. [Mode/icon readback](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifolderview2-getviewmodeandiconsize), [sort columns](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifolderview2-setsortcolumns), [column order](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icolumnmanager-setcolumns).

Navigating from owned A to owned B exercises navigation saving; explicit `Destroy` exercises browser teardown. Entirely new native browser instances then revisit A and B without applying any view-setting setter, and require exact native restoration. A separate actual `EBO_NOPERSISTVIEWSTATE` instance applies a different view to A, closes, and must leave A's prior saved state and B's independent state intact. This proves the suppression branch as well as the remembering branch; the test never changes the global cabinet policy.

Every native view member's canonical parent must equal the owned folder before it is accepted. Before/after file snapshots compare volume and 128-bit file identity, complete content, size, modified/change time and attributes. Clipboard sequence and input-desktop identity must remain unchanged. Two WinEvent observers monitor the fixture's private desktop and the process's original desktop. They permit only the explicit owned-frame realization phase; polling after that phase rejects all visible private-desktop windows. Filesystem cleanup is limited to the original create-new root, with its original identity, expected members and no reparse points. The native view-state records are left to the disposable VM's lifetime; the test never deletes shared Shell Bags.

The standalone test compiles cleanly with MSVC `/W4` and skips locally before any Shell mutation. The disposable run at `8191269` failed to materialize an `IShellItemArray` despite the view's eight-item count; earlier direct `GetItem` readback also failed. The current fixture instead obtains each actual child PIDL through `IFolderView::Item`, reads the original native parent with `GetFolder`, and binds the child with `SHCreateItemWithParent`. It retains the count and canonical-parent assertions. The run at `7f06241` passed this readback for owned folder A and recorded its applied native settings, but failed following the next browse. The fixture now clears completion before each asynchronous `BrowseToObject`, since `OnNavigationPending` may arrive after the wait begins. Actual native restoration remains **unverified pending a successful disposable-runner execution**. A successful setter, a property-bag name, or a disabled persistence flag alone is not evidence that settings survived destruction and recreation. Microsoft also documents that the view-state store has a finite capacity and may evict long-unvisited folders; the application does not promise permanent retention. [Native view child PIDLs](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifolderview-item), [original native folder binding](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifolderview-getfolder), [bind child to parent](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-shcreateitemwithparent), [view-state property-bag lifetime](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-shgetviewstatepropertybag).
