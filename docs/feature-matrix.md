Hardware, edition, policy, associations and installed providers can legitimately disable a native command. Host guesses about availability cannot. Native delegation requires the actual provider, target, site and state; it does not certify arbitrary provider or hardware behavior.

Native namespace selections retain the complete original array/count/site without a 100,000-item rejection or truncation. Filesystem/folder/link eligibility uses documented `GetAttributes(AND | ALLITEMS)`: plain AND missed a final counterexample on the tested native 100,001-item array. Three real native arrays and a mock full-array/site provider fixture verify last-file, last-nonlink and last-virtual-item truth without creating 100,000 physical files. Optional path/residency/type inspection has a 100,000-item budget; above it those facts are explicitly unknown, registered native provider state remains available, and unchecked SendTo/Offline/Cast fallbacks are rejected. [Attribute aggregation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemarray-getattributes)

Known ordinary single-item associations provide a fast negative prefilter; positive, multiple, shortcut and unknown custom-namespace states remain pending until the catalog worker reads the complete actual native menu with the original view site. A validated full CIDA snapshot preserves every identity; providers without CIDA retain the correctly marshaled original array. Ribbon-only Remove properties and redirected application-shortcut compatibility read the exact registered menu. Native single/mixed/16-item/5,001-item arrays and a non-agile 100,001-item mock verify exact leaf states, missing/ambiguous/failure output and cancellation without invocation. Native menus have depth/4,096-entry limits, retained providers have 256 native subcommands, and breadcrumbs have time/cancellation/4,096-child/size limits. An incomplete breadcrumb snapshot reports its stop reason. Saved metadata has explicit parsing limits; normal Windows.ModernShare follows its native provider state.

Compatible pending selection verbs share one complete native-menu worker per generation; registered-only and differently targeted providers remain separate. State-only creation leaves delayed cascades lazy and rejects activation; eligible state-only requests temporarily omit documented resource verbs, with exact restriction restoration. Normal menus retain their complete native routes. Native root-leaf comparisons cover 1/2/16/5,001/10,000-item all-file/final-folder arrays and registered Remove properties. One selection-menu work reservation survives cancellation until provider/COM cleanup, preventing overlapping stale native queries. State equivalence and whole-App timing are separate requirements; the accepted quiet benchmark records complete command readiness and retains earlier 45-second failures in [performance.md](performance.md). Worker shutdown requires the creator to retain its exact borrowed desktop connection and initialized STA/sites through the final drain. The drain waits for the App's workers and closes never-attached keepalive duplicates; native helper threads can retain the creator connection independently. [Worker lifetime and timing contract](architecture.md#command-state-and-invocation)

Desktop/taskbar/start-menu hosting and replacing the system-wide Win+E association are separate system integration tasks. The app runs alongside the Windows shell. HomeGroup was removed from the target Windows 10 version; Windows 11-only features are outside this baseline.
