# Windows 10 feature matrix

This inventory compares the [Windows 10 22H2 baseline](windows-10-research.md) with the current source. A binding does not establish behavioral or visual parity. **Wired** means explicit host code exists; **Shell** means an actual Windows provider/API is used, with its native availability/state; **Partial** identifies a production or verification limit; **Gap** identifies missing behavior; **Unproven** identifies an unestablished comparison. Acceptance criteria are requirements until test reports establish them.

Source audit: 2026-10-04. The [older CI run at ce231210](https://github.com/ProtonDev-sys/windows-explorer/actions/runs/37169510842) verified the earlier two-test/72-check baseline, not the subsequent Ribbon, theme, breadcrumb and command changes. Current runtime evidence is tracked by the test reports, [visual report](headless-visual.md), [performance report](performance.md), [search provider report](search-options-verification.md), and [theme compatibility report](theme-compatibility.md). Visible desktop/device/recipient tests are excluded.

Hardware, edition, policy, associations and installed providers can legitimately disable a native command. Host guesses about availability cannot. Native delegation requires the actual provider, target, site and state; it does not certify arbitrary provider or hardware behavior.

Native namespace selections retain the complete original array/count/site without a 100,000-item rejection or truncation. Filesystem/folder/link eligibility uses documented `GetAttributes(AND | ALLITEMS)`: plain AND missed a final counterexample on the tested native 100,001-item array. Three real native arrays and a mock full-array/site provider fixture verify last-file, last-nonlink and last-virtual-item truth without creating 100,000 physical files. Optional path/residency/type inspection has a 100,000-item budget; above it those facts are explicitly unknown, registered native provider state remains available, and unchecked SendTo/Offline/Cast fallbacks are rejected. [Attribute aggregation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemarray-getattributes)

Known ordinary single-item associations provide a fast negative prefilter; positive, multiple, shortcut and unknown custom-namespace states remain pending until the catalog worker reads the complete actual native menu with the original view site. A validated full CIDA snapshot preserves every identity; providers without CIDA retain the correctly marshaled original array. Ribbon-only Remove properties and redirected application-shortcut compatibility read the exact registered menu. Native single/mixed/16-item/5,001-item arrays and a non-agile 100,001-item mock verify exact leaf states, missing/ambiguous/failure output and cancellation without invocation. Native menus have depth/4,096-entry limits, retained providers have 256 native subcommands, and breadcrumbs have time/cancellation/4,096-child/size limits. An incomplete breadcrumb snapshot reports its stop reason. Huge selections omit optional status metadata instead of eager content scans. Saved metadata and the separate Share payload fixture helper have explicit limits; normal Windows.ModernShare follows its native provider state.

Compatible pending selection verbs share one complete native-menu worker per generation; registered-only and differently targeted providers remain separate. State-only creation leaves delayed cascades lazy and rejects activation; normal menus retain synchronous cascades. Native root-leaf comparisons cover 1/2/16/5,001/10,000-item all-file/final-folder arrays and registered Remove properties. One default-menu work reservation survives cancellation until provider/COM cleanup, preventing overlapping stale native queries. Correct state equivalence does not establish acceptable large-selection latency: menu preparation, selection notifications and host reentrancy require whole-app timing evidence, and the measured large native query remains expensive. Worker shutdown also requires the creator to retain its exact borrowed desktop connection and initialized STA/sites through the final drain. The drain waits for the app's workers and closes never-attached keepalive duplicates; native helper threads can retain the creator connection independently. [Worker lifetime and timing contract](architecture.md#command-state-and-invocation)

Desktop/taskbar/start-menu hosting and replacing the system-wide Win+E association are separate system integration tasks. The app runs alongside the Windows shell. HomeGroup was removed from the target Windows 10 version; Windows 11-only features are outside this baseline.
