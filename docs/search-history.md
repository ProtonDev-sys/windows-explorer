# Search history and suggestions

Normal windows attach Windows' `IAutoComplete2` to the search edit using an owned `IEnumString` provider. Suggestions use `ACO_AUTOSUGGEST | ACO_UPDOWNKEYDROPSLIST`; typing remains ordinary editable query text. Search history updates only after successful search navigation, with the most recent query first and a maximum of 20 entries. [Native autocomplete](https://learn.microsoft.com/en-us/windows/win32/api/shldisp/nn-shldisp-iautocomplete), [Autocomplete options](https://learn.microsoft.com/en-us/windows/win32/api/shldisp/ne-shldisp-autocompleteoptions)

History lives in `%LOCALAPPDATA%\WindowsExplorer\search-history.dat`. Its bounded UTF-8 format validates count, lengths, Unicode, duplicates, and complete consumption. Saving writes a uniquely named temporary file, flushes it, and atomically replaces the destination; invalid input leaves existing history intact. It does not write Explorer's shared history registry. Both per-user and machine DisableSearchBoxSuggestions policy are read before attachment or persistence. The native policy prevents recent-query suggestions and future history recording. [Policy reference](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-windowsexplorer#disablesearchboxsuggestions)

The enumerator owns every string, uses COM allocation for returned entries, and gives clones independent cursor state. Updating its snapshot cannot retain an application object or an edit-window pointer. Autocomplete attaches only to an owned edit on the owning STA, and shuts down before that edit is destroyed. Headless application mode forbids attaching the suggestion popup.

Four console-test groups exercise Unicode persistence, bounded MRU ordering, malformed input and preserved outputs, enumerator allocation/clone/reset/replacement, and the explicit headless rejection. A separate hidden fixture attaches the actual native autocomplete on a worker's private desktop created before COM, verifies its real options, checks the dropdown remains invisible, and disables it before teardown. Fixtures never load or log personal history and never modify policy. These tests establish the host's native suggestion/MRU behavior; they do not certify equivalence to every internal Explorer suggestion provider.

Windows 10 2004 also permits resizing the search box by dragging its left edge. The app stores that width independently of window width and clamps it to the available row. The hidden host verifies an actual splitter drag through owned window messages. [Windows 10 20H1 changes](https://learn.microsoft.com/en-us/windows-insider/archive/new-in-20h1)
