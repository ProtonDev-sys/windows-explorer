# Disposable hosted pin persistence fixture

The existing Windows build workflow has an explicit `owned_profile_mutation` input, false by default. Push, pull-request, and ordinary manual runs retain the existing read-only/headless build and transfer jobs. An explicit true manual dispatch instead creates only the separate `app_pin_persistence_owned` job on a fresh GitHub-hosted Windows VM. Select `normal-flow` or `final-destroy-only`; each is a separate dispatch and a fresh profile. Local and self-hosted execution are forbidden. Do not forge CI environment values or issue a local admission marker.

The default-OFF CMake fixture first uses one genuine enabled canonical native `pintohome` invocation as setup for its independently verified newly created GUID folder. This setup has its own receipt and does not count as an App callback, normal-flow persistence, or final-destroy coverage. A fresh normal App must independently admit the actual pinned Home row; it then measures the real native App `unpinfromhome` callback and fresh-source unpin persistence. App pin persistence remains unmeasured. The restrictive compiled fixture guard verifies canonical identity and the full volume/128-bit FileID before the original provider Invoke and rechecks the original source after releasing temporary interfaces. It never substitutes a provider, manually calls an App handler, or mutates an unowned pin. Complete original pinned inventory must be restored on success and failure, within the existing 60-second recovery bound. The original App action bound is 180 seconds and the outer CTest bound remains 300 seconds. A provider failure, missing route, source loss, timeout, or unproved restoration is a test failure, never coverage.

This is a disposable-profile test: normal App preferences/recent history may change within that fresh VM. Pinned inventory restoration is exact; it is not a general profile-restoration promise. No existing local user profile is authorized. The final-destroy-only case measures its separate teardown timing and must not be interpreted as normal-flow persistence.

Public artifacts contain actual checkout SHA, executable hashes before/after, run/attempt/case/job identities, full source hash censuses before/after build and after run, warning-free configure/build logs, selected native stdout/stderr and JUnit results. The census covers all actual include/src/tests/resources files, CMake, this workflow, and this document; it is checked against a clean checkout with HEAD equal to GITHUB_SHA. No ignored author-local proposal/manifests, marker bytes, credentials, or private local data are uploaded. Native receipts may contain the fixture's new disposable GUID paths and native status/identity values. Exit success requires exactly one actual passing selected test with no skip and immutable source/executable identities. Source review and compilation alone establish no native pin persistence result.
