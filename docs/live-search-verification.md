# Classic search as you type

The target is the classic results-pane experience on the inspected Windows 10 Home 22H2 build 19045.6466. Microsoft's [Windows Search overview](https://learn.microsoft.com/en-us/windows/win32/search/-search-3x-wds-overview) describes Explorer's instant search box and filtering the items shown in the window. It recommends the Shell search data source, which can use indexed results or native enumeration in an explicit unindexed scope. [ISearchFolderItemFactory](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-isearchfolderitemfactory) supplies the native query folder. Neither source establishes a particular Explorer debounce duration. The separate [suggestions audit](search-suggestions-research.md) records the version-dependent 2019 matching-file dropdown; this implementation does not claim that popup or a private OneDrive provider.

`LiveSearchPolicy` retains the literal edit text, one replaceable pending request and a generation identifying issued work. Ordinary typing waits for a 250 ms host debounce and an available navigation slot. Enter replaces pending work with an immediate explicit request, including when the same text already has automatic results. Clearing the edit or Escape requests the saved native origin immediately. Programmatic text updates and external navigation/teardown invalidate issued and queued work. The timer uses monotonic milliseconds, with saturated deadline arithmetic.

Only successful completion of the current explicit query can commit its literal. Automatic parser or navigation failures retain the last valid view and do not request a modal error or write search history. A stale or duplicate completion cannot change the policy's committed text. The host must match the target native PIDL and wait for actual navigation completion; acceptance by `BrowseToObject` alone is insufficient. The scheduling API performs no filesystem, registry, index, clipboard or history I/O. Literal UTF-16, whitespace and spelling are preserved; invalid UTF-16, embedded NUL and input beyond the native query bound are rejected without changing state.

The standalone `live_search_tests` checkpoint passed **5/5 groups** on 2026-10-04 with MSVC `/W4` and no warnings. It uses a private non-input desktop and fresh owned three-file folders. Real native Search Folder enumeration verifies exact volume/128-bit file identities for the final Unicode query, an obsolete intermediate query, an immediate Enter query and a cancelled all-files query. It also checks successful explicit commit, duplicate/stale/altered-token refusal, burst replacement, navigation backpressure, immediate origin identity restoration, programmatic suppression, cancellation, invalid input and timer overflow. All owned source identities, contents, creation/write/change timestamps, attributes and entry counts remain unchanged; the input desktop and clipboard remain unchanged.

On this build the harmless incomplete literal `System.Size:>` is repaired by the native parser and returns `S_OK`. The test records that observation rather than asserting that incomplete AQS always fails. Deterministic failed-completion checks exercise the error policy while retaining an actual valid native query and its exact result identity. The known native filename-prefix compatibility guard remains in force; no guarded native crash query is executed. This module checkpoint does not substitute for the application's separate headless edit/timer/navigation integration checks.

An immediate native navigation rejection with `HRESULT_FROM_WIN32(ERROR_BUSY)` now reschedules only the identical unfinished request after 100 ms. The request keeps its generation, literal and explicit Enter marker; it commits nothing until actual matching navigation completion. Newer edits, programmatic replacement, Escape, external navigation and a completed request reject an old retry. Deadline arithmetic remains saturated. This handling follows an observed native browser rejection; the public [BrowseToObject contract](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iexplorerbrowser-browsetoobject) documents asynchronous navigation and requires completion/failure events rather than treating acceptance as completion.
