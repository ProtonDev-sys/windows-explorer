The application has a dedicated `--headless-visual` mode. Before COM or any window is created, `PrivateDesktop` creates a uniquely named Windows desktop and attaches the UI thread. It deliberately requests no desktop-switch access and never activates that desktop. Visible native controls on that private desktop can paint normally while the user's input desktop remains unchanged. The application verifies isolation before displaying or capturing any window and checks that none of its process windows is visible on the input desktop. [Microsoft: SetThreadDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddesktop), [desktop access rights](https://learn.microsoft.com/en-us/windows/win32/winstation/desktop-security-and-access-rights)

`captureWindowPng` captures the actual HWND through `PrintWindow(PW_RENDERFULLCONTENT)`, using a top-down GDI DIB and the native WIC PNG encoder. Windows can obtain an existing painted native surface instead of dispatching a new print message, so the final theme/layout pass must complete normal native repainting first. The capture does not draw a substitute screenshot or read the interactive screen. Color, ink, unpainted-sentinel and visible-control checks reject blank output. Each PNG has a JSON inventory of actual HWND classes, text and geometry, together with the desktop, native DPI, requested layout DPI and visibility checks. Optional DWM frame trimming removes the system's invisible resize borders using measured frame bounds. Output files use create-new semantics. [PrintWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow), [WIC encoding](https://learn.microsoft.com/en-us/windows/win32/wic/-wic-creating-encoder), [DWM frame bounds](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)
