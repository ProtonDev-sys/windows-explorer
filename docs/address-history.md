# Typed address history

The address dropdown and F4 use a typed-address MRU, separate from the Back/Forward travel log and search history. Only an explicit typed address whose native navigation finishes at the expected Shell identity becomes a new entry. Failed, cancelled or redirected navigation does not record that pending input. Original Unicode spelling, spaces, environment-variable text, UNC names and virtual Shell names are retained. Case-insensitive ordinal duplicates move to the front with the newest original spelling. The application limits its own list to 20 entries; this is not claimed as a Windows history limit.

Explicit typed input can also launch an application, document or URL when it is not a native folder destination. The host uses public [ShellExecuteEx target, parameter and working-directory fields](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow): URLs stay intact, executable argument quoting and Unicode are retained, and environment substitution applies only to the filename/directory fields. The physical current folder supplies the working directory when available. This launcher is forbidden in headless mode, and launch success does not add a folder-navigation MRU entry. Three separate typed-address groups check parsing, rejected-input output preservation and an owned fake dispatcher; they launch no associated application or native command.

Normal startup loads `%LOCALAPPDATA%\WindowsExplorer\address-history.dat`. When that file is absent, it can import Explorer's `TypedPaths` values once, read-only. An existing empty codec stays empty, so deleting app history does not resurrect imported entries. Native `urlN` entries sort by their numeric suffix; REG_SZ and REG_EXPAND_SZ are accepted without expanding the original text. Invalid types, names and values are ignored. The application never writes or clears the shared native key and never logs personal address strings. Headless application mode uses only its fixture-owned in-memory model and skips native history and persistent app-history access.

The separate versioned UTF-8 codec checks complete consumption, count, string lengths, Unicode, embedded NULs and ordinal duplicates. Load errors preserve the caller's previous list. Saving validates and encodes the entire list first, flushes an exclusively created temporary in the same directory and uses a native rename to publish it. The shared state writer also serves app preferences, search history, the Quick Access Toolbar model and native Ribbon settings. It reads the exact held file's DACL with [GetKernelObjectSecurity](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-getkernelobjectsecurity), supplies that descriptor at [CreateFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) creation, and verifies exact ACE order, rights, flags and inheritance control on the empty stage before writing private bytes. Existing identity and security are checked again before publication. An existing reader that denies replacement, a read-only target or invalid input preserves the old bytes and identity. Creation time, basic attributes and native filesystem compression survive successful replacement. Temporary cleanup acts on the created file handle. Reparse and encrypted history targets are refused rather than followed or silently decrypted.

The documented [REST_NORECENTDOCSHISTORY policy](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ne-shlobj_core-restrictions) disables all MRU lists. The typed-address host checks it through [SHRestricted](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shrestricted) before loading, importing, displaying or persisting history. It also suppresses its typed history when Folder Options' `ShowRecent` privacy value is explicitly zero. Microsoft's [File Explorer privacy instructions](https://support.microsoft.com/en-gb/windows/experience/fileexplorer/file-explorer-in-windows) establish that this choice hides recent files in Quick access; applying it to the host's typed-address MRU is an additional privacy choice, not a claim about a documented native TypedPaths contract. Search-suggestion policy is separate.

Right-clicking the breadcrumb address bar opens Copy address, Copy address as text, Edit address and Delete history. Windows 10 build 19045 supplies these exact labels and command IDs through `explorerframe.dll` menu resource 272; the host validates that signature and retains a separate loaded menu. Copy address uses the original folder's Shell data object, while Copy address as text uses its [absolute editing name](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-sigdn) as Unicode text. Both operate on an owned PIDL/text snapshot, independent of later navigation. Edit refuses a superseded location. Keyboard requests use the address-bar bounds. The normal edit control retains its standard text context menu.

Delete history clears only this application's typed MRU after successfully publishing an empty codec. Failed saving preserves the in-memory list; pending typed navigation cannot re-add the deleted entry. Windows Folder Options' Clear action concerns Windows' separate history. Headless mode blocks clipboard publication, persistent deletion and popup display. Read-only host checks compare all four commands/labels with the actual installed menu, inspect enabled states and retained identity/text, exercise the owned Edit route, and verify clipboard/history and input-desktop isolation. Session-history and recent-search menus likewise retain the exact displayed targets while their native popup loop pumps messages; actual owned navigation verifies history selection after forward truncation.

Five headless groups verify exact Unicode/environment/UNC/virtual round trips, ordinal MRU/import priority, malformed and oversized input, retained caller state and existing-file data, real sharing/read-only failures, and absence of temporary files. The additional security group runs actual address-history, search-history, preferences and QAT encoders/decoders against six exclusively owned legacy-inherited, legacy-explicit, protected, modern-inherited, modern-protected and deny-data-write ACL profiles. Independent `GetFileSecurityW` readback compares complete DACLs and inheritance control without reporting trustees or personal paths. It also verifies new same-volume replacement identities, retained creation time/attributes/compression and exact original data, identity, timestamps, permissions and directory membership after failed sharing/read-only saves. This focused Release `/W4` build was warning-free and passed on a never-switched private desktop in 0.304 seconds; clipboard sequence and input-desktop isolation remained unchanged. A separate native Ribbon fixture reuses the same security profiles with actual `saveSettings`/`loadSettings` and minimized/dock/QAT state readback; its coordinated suite result is recorded separately. Registry parsing uses an exclusively created volatile GUID key containing only synthetic entries. Real key value-count and last-write readbacks prove the parser did not write it. The fixture never reads personal TypedPaths, changes user privacy or policy settings, invokes navigation, or creates visible input-desktop windows. Application popup/navigation integration is checked separately by the host smoke suite.
