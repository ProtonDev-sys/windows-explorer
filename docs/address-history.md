# Typed address history

The address dropdown and F4 use a typed-address MRU, separate from the Back/Forward travel log and search history. Only an explicit typed address whose native navigation finishes at the expected Shell identity becomes a new entry. Failed, cancelled or redirected navigation does not record that pending input. Original Unicode spelling, spaces, environment-variable text, UNC names and virtual Shell names are retained. Case-insensitive ordinal duplicates move to the front with the newest original spelling. The application limits its own list to 20 entries; this is not claimed as a Windows history limit.

Explicit typed input can also launch an application, document or URL when it is not a native folder destination. The host uses public [ShellExecuteEx target, parameter and working-directory fields](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow): URLs stay intact, executable argument quoting and Unicode are retained, and environment substitution applies only to the filename/directory fields. The physical current folder supplies the working directory when available. This launcher is forbidden in headless mode, and launch success does not add a folder-navigation MRU entry. Three separate typed-address groups check parsing, rejected-input output preservation and an owned fake dispatcher; they launch no associated application or native command.

Normal startup loads `%LOCALAPPDATA%\WindowsExplorer\address-history.dat` and can append a read-only import of Explorer's `TypedPaths` values. App-owned entries retain priority. Native `urlN` entries sort by their numeric suffix; REG_SZ and REG_EXPAND_SZ are accepted without expanding the original text. Invalid types, names and values are ignored. The application never writes or clears the shared native key and never logs personal address strings. Headless application mode uses only its fixture-owned in-memory model and skips native history and persistent app-history access.

The separate versioned UTF-8 codec checks complete consumption, count, string lengths, Unicode, embedded NULs and ordinal duplicates. Load errors preserve the caller's previous list. Saving validates and encodes the entire list first, flushes an exclusively created temporary in the same directory and uses a native rename to publish it. An existing reader that denies replacement, a read-only target or invalid input preserves the old bytes and identity. Existing DACL and basic attributes are retained. Temporary cleanup acts on the created file handle. Reparse and encrypted history targets are refused rather than followed or silently decrypted.

The documented [REST_NORECENTDOCSHISTORY policy](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ne-shlobj_core-restrictions) disables all MRU lists. The typed-address host checks it through [SHRestricted](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shrestricted) before loading, importing, displaying or persisting history. It also suppresses its typed history when Folder Options' `ShowRecent` privacy value is explicitly zero. Microsoft's [File Explorer privacy instructions](https://support.microsoft.com/en-gb/windows/experience/fileexplorer/file-explorer-in-windows) establish that this choice hides recent files in Quick access; applying it to the host's typed-address MRU is an additional privacy choice, not a claim about a documented native TypedPaths contract. Search-suggestion policy is separate.

Windows Folder Options' Clear action clears Windows' own history; it does not clear this application's separate codec. Close the application and delete its `address-history.dat` to clear only its stored typed list. A subsequent allowed startup can import the native typed list again. No application address-history deletion control is advertised without a verified native interaction.

Four headless groups verify exact Unicode/environment/UNC/virtual round trips, ordinal MRU/import priority, malformed and oversized input, retained caller state and existing-file data, real sharing/read-only failures, and absence of temporary files. Registry parsing uses an exclusively created volatile GUID key containing only synthetic entries. Real key value-count and last-write readbacks prove the parser did not write it. The fixture never reads personal TypedPaths, changes user privacy or policy settings, invokes navigation, or creates visible input-desktop windows. The standalone `/W4` build and all four groups passed; application popup/navigation integration is checked separately by the host smoke suite.
