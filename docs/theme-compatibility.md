# Windows 10 theme compatibility

The host calls `initializeProcessTheme` before creating its first HWND or native Ribbon. Auto reads the DWORD `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`; an absent or invalid value uses Light. Light and Dark are process overrides. The implementation never writes this key, calls `SetSysColors`, changes the input desktop, or changes Windows accessibility settings. Painting reads cached state and borrowed brushes, with no registry I/O.

High contrast takes priority over all three modes. `SPI_GETHIGHCONTRAST` detects it, and the palette uses paired `GetSysColor` foreground/background values: WINDOW/WINDOWTEXT for content, BTNFACE/BTNTEXT for Ribbon/status, ACTIVECAPTION/CAPTIONTEXT for caption. The host refreshes on WM_SETTINGCHANGE, WM_THEMECHANGED and WM_SYSCOLORCHANGE. A failed high contrast query conservatively uses system colors. These are documented [high contrast APIs](https://learn.microsoft.com/en-us/windows/win32/winauto/high-contrast-parameter) and [system colors](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getsyscolor).

The [documented Ribbon color properties](https://learn.microsoft.com/en-us/windows/win32/windowsribbon/ribbon-color) are `UI_PKEY_GlobalBackgroundColor`, `UI_PKEY_GlobalHighlightColor`, and `UI_PKEY_GlobalTextColor`, set through IPropertyStore with VT_UI4 HSB values and Commit. They are color transformations, not literal RGB surface colors. Windows 8 and later couple global highlight to global background. Those public properties alone do not produce Windows 10 Explorer's flat dark Ribbon. The implementation therefore preserves the native Light values, uses the Ribbon's native dark compatibility property, and restores the captured native values when leaving Dark. The native dark toggle itself changes the reported global colors. Call `forgetRibbonTheme(framework)` before destroying/resetting that framework; the cache retains no COM references.

Windows 10 native dark controls require compatibility APIs which Microsoft has not made a stable public Win32 contract. The relevant missing contract is tracked in [Microsoft WindowsAppSDK issue 5543](https://github.com/microsoft/WindowsAppSDK/issues/5543). Native Ribbon property index 2004 (VT_BOOL, the normal Ribbon property GUID format) is likewise undocumented; its original implementation is described by [BowPad's author](https://github.com/stefankueng/BowPad/blob/main/src/MainWindow.cpp). The helper does not copy that implementation.

The helper loads uxtheme.dll only with LOAD_LIBRARY_SEARCH_SYSTEM32 and resolves ordinals 133 (per-window dark permission), 135 (process theme policy), and optional 136 (menu theme cache flush). Microsoft [PowerToys](https://github.com/microsoft/PowerToys/blob/main/src/modules/ZoomIt/ZoomIt/Utility.cpp) also uses these internal APIs. Ordinal 135 has different ABIs: build 17763 uses `bool(bool)`; recognized builds 18362/18363, 19041–19045, 22000, 22621/22631 and 26100 use the PreferredAppMode enum. Unknown builds never call these ordinals. Build 17763 cannot force Dark while Windows prefers Light, so the requested unsupported override returns S_FALSE and reports actual Light. Missing required exports also retain Light.

Win11's documented [DWMWA_USE_IMMERSIVE_DARK_MODE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute) starts at build 22000. On recognized Win10 builds, attributes 20/19 and the named user32 SetWindowCompositionAttribute dark-color selector 26 are compatibility paths, not promises of public Win10 support. HWND mutations reject other processes and threads. The helper preserves existing activation when refreshing WM_NCACTIVATE; it does not activate a window. Native Shell ItemsView styling remains intact, while public ListView/TreeView color messages update their background/text.

`theme_tests` runs entirely on a private desktop which is never switched to the input desktop. On Windows 10 build 19045, actual native PrintWindow/WIC pixels verify Ribbon/content #202020, navigation #191919, and active caption #000000. These match flat regions measured from the [online stock Explorer dark screenshot](https://cdn.mos.cms.futurecdn.net/C8ATUR84F4Tcs3K5XQ5YjC.jpg), whose provenance and sampling are recorded in `artifacts/reference/dark-palette.json`. Address #191919 and status #333333 are palette/reference checks; full application scenes test their layout separately. White/disabled text, borders and hover colors are fallback values, not pixel claims from the publisher's resampled JPEG. The tests additionally verify Dark-to-Light restoration, rejected cross-thread/foreign HWND mutation, unchanged Windows theme/high contrast settings, and absence of process-owned visible windows on the input desktop. High contrast policy is tested without altering the user's high contrast configuration. Unsupported OS builds skip native dark paint assertions and retain the native Light path.
