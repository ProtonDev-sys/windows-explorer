# Native saved-search query verification

Ordinary unqualified terms, quoted words, multiword queries and typed generic terms can now be saved, reopened, edited and saved again. The writer preserves the native parser's generic property and comparison instead of storing null-property leaves that depend on parser input offsets. It normalizes only those generic leaves and restated Generic.String Blurb tokens; named relative-date siblings retain their original unresolved expressions.

The implementation uses public [IConditionFactory::Resolve](https://learn.microsoft.com/en-us/windows/win32/api/structuredquery/nf-structuredquery-iconditionfactory-resolve) with the original IQuerySolution context. [SQRO_DONT_RESOLVE_DATETIME](https://learn.microsoft.com/en-us/windows/win32/api/structuredquery/ne-structuredquery-structured_query_resolve_option) preserves relative dates, and DONT_SPLIT_WORDS preserves the parser's word groups. The resulting generic condition may be a compound: for example, an unqualified integer can search both Generic.Integer and Generic.String. The writer retains that full expansion.

Resolved numeric/Boolean scalars are restated with public [IQueryParser::RestateToString](https://learn.microsoft.com/en-us/windows/win32/api/structuredquery/nf-structuredquery-iqueryparser-restatetostring), parsed again, and checked for the identical canonical property, operation, scalar type and value before serialization. This lets Windows produce its unresolved XML-compatible scalar tokens rather than converting a resolved integer into a plain string with different meaning. Serialization still uses only the [public saved-search elements and attributes](https://learn.microsoft.com/en-us/windows/win32/search/-search-savedsearchfileformat), exclusive UTF-8 creation and the existing tree/length bounds.

Saving over an existing query now follows the native Save dialog's overwrite approval. The dialog preserves its default options and explicitly retains [FOS_OVERWRITEPROMPT](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-_fileopendialogoptions). `SearchSaveMode::UserConfirmed` is used only after that dialog succeeds; the default writer still uses CREATE_NEW. Validation and complete UTF-8 serialization happen before any output is created. A replacement is written and flushed to an exclusively created file in the same directory, retains the target's DACL, creation time, ordinary attributes and native compression, and is published with public [SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle) and [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info). Windows 10 POSIX rename semantics keep existing read handles referring to the old file while later opens find the new complete file. DELETE-access preflight respects a reader that denies replacement. Temporary cleanup uses its owned handle rather than a possibly reused pathname.

After the handles close, the writer sends the documented [Shell change notification](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify) asynchronously. The native saved-folder provider can retain an earlier parsed condition until its owning STA processes notifications. Headless replacement checks therefore pump that STA and require the exact new native result identities within five seconds, while checking the newly published XML immediately. Production performs no result scan or polling and does not wait for every Shell notification recipient.

The confirmed-save fixture covers existing and new paths through all three scope APIs, native reopening and metadata import, hidden targets, compressed targets, invalid input, default no-overwrite, a sharing lock and the read-only attribute. Every rejected save preserves exact original bytes, file identity, DACL and timestamps and leaves no temporary/backup files. Source identities and contents remain unchanged. EFS-encrypted and reparse targets are explicitly refused; this replacement path does not claim preservation of arbitrary alternate data streams. The clean `/W4` private-desktop checkpoint and an independent repeat passed all 17 search and saved-metadata groups, with the repeat taking 7.33 seconds.

Native Windows 10 operator verification distinguishes `word eq` (COP_WORD_EQUAL) from `wordmatch` (COP_WORD_STARTSWITH). Read-only inspection of the installed StructuredQuery.dll XML vocabulary identified both spellings; actual native saved-folder results established the mapping. The previous equality-to-wordmatch mapping could broaden a saved whole-word query to prefixes. Writer and reader now agree with the native loader. Explicit System.FileName word-prefix conditions remain blocked by the existing AST compatibility guard before native execution; none of the verification fixtures enumerate that rejected condition.

On Windows 10 Home 22H2 build 19045, 16/16 isolated headless search and saved-metadata groups pass, including 23 generic-query cases and 17 typed date cases. Each case compares exact volume/file identities through the original live search, the native .search-ms loader, the restored host query and a second saved native search. Known sets distinguish word prefixes from complete words, quoted multiword behavior, Today from historical modification times, recursive results from shallow results, Unicode names and equal basenames in different folders. Numeric/fractional terms, ranges/comparators, OR/NOT, mixed generic/property queries and relative-date siblings are covered. A saved generic search also discovers a newly matching owned file, excludes an outside file, and stops returning the same identity after it is renamed to a nonmatching name.

The unindexed Windows 10 generic provider in this fixture matches both complete words of a quoted multiword query in separated/reversed filenames as well as an adjacent phrase. Tests preserve and compare that observed native behavior; they do not substitute an application phrase matcher. The fixtures create no windows, use no global Explorer commands, modify no settings/index/clipboard/Recycle Bin, and enumerate only exclusively owned temporary scopes. This PC coverage remains a metadata/PIDL scope check without user-wide enumeration. Arbitrary external saved-search shapes and unsupported scopes still receive the reader/writer's explicit error rather than a changed query meaning.

Multiple-location and native Library searches now retain their union throughout live search, import, query refinement and re-save. Library scopes expand through the public IShellLibrary location list, without writing default Libraries or changing indexing settings. An exclusively owned two-location Library fixture verifies equal basenames in separate folders, nested matches, per-location shallow search and discovery of a newly added match. Transient native multi-location snapshots are retried for at most five seconds in tests; production performs no recursive application scan.

`SearchScopeRule` preserves each included/excluded location and its recursion flag. Four owned scope-rule fixtures prove exact identities across native XML, live condition folders, import and re-save: mixed include recursion, recursive child exclusions, multiple deep exclusions and overlapping include roots. Included locations remain in the native factory scope; documented ItemFolderPath/ItemPath conditions constrain mixed recursion and exclusions. At most 256 locations are accepted. Exclusive creation, rejected-input no-output checks and existing-file byte/file-identity preservation remain covered. Failed metadata reads preserve every caller field, including the union array and scope-rule vector.

The [documented saved-search format](https://learn.microsoft.com/en-us/windows/win32/search/-search-savedsearchfileformat) permits shallow exclusions. Owned unindexed Windows 10 observations show these cases need separate fidelity handling: a shallow exclusion was ignored, a recursive exclusion equal to an included root was ignored, and an excluded direct child of a shallow include retained the child folder object. These observations are limited to the tested unindexed provider; no indexed behavior is claimed. Editable import/save rejects those combinations, while external files remain openable in the native Shell viewer. Virtual exclusions and a virtual included root mixed with shallow physical roots also remain native-view-only.

Native kind unions preserve actual property values through typed condition leaves and the native parser's validated RestateToString output. Five fixtures compare native saved results with imported live results and re-save: document/picture, case-normalized picture/folder, folder-only, repeated document and item/picture. The installed loader treats a sole item entry as its all-item sentinel, item/picture as picture-only, and repeated item entries as an empty union. Repeated all-item sentinels remain native-view-only rather than being changed to all results. These are loader observations, not invented set-union semantics.

Filesystem scope names with a literal unpaired percent sign preserve native identities. Exact known-folder roots persist through public knownFolder GUIDs and canonical Shell identity; Network and Control Panel coverage performs metadata/PIDL checks only, without enumerating those user-wide scopes. Arbitrary ProgIDs are rejected before any native class conversion.

Typed Date modified ranges now save through the documented native condition format. The parser represents an inclusive `start..end` date range as two unresolved date values. The writer uses public [IConditionFactory::MakeLeaf](https://learn.microsoft.com/en-us/windows/win32/api/structuredquery/nf-structuredquery-iconditionfactory-makeleaf) to serialize their equivalent greater-than-or-equal and less-than-or-equal scalar bounds inside an andCondition. The unresolved values remain unchanged, including relative Today and Tomorrow. The reader checks the full resolved condition meaning while allowing the native parser to distribute NOT over a range.

The owned date fixture verifies leap day, a year boundary, strict day comparisons, inclusive ranges, negation, size refinement and explicit UTC bounds. Seventeen timestamped files include exact midnight and the last 100 nanoseconds of the selected day. All four search routes return the same expected file identities; file contents and modification times remain unchanged. Current-zone conversion also verifies the native 23-hour spring day and 25-hour autumn day on this PC, without changing its time zone. These are native [AQS date and range semantics](https://learn.microsoft.com/en-us/windows/win32/search/-search-3x-advancedquerysyntax), rather than a fixed 24-hour application date filter.

When restating an imported, factory-constructed UTC second condition, this native parser drops its UTC suffix and emits a localized time. The reader accepts canonical ISO UTC text only after public resolution proves an exact one-second interval and reparsing reproduces the original property, operation, semantic type and opaque native value. It does not decode native date tokens or freeze relative dates. Invalid February dates are tolerated by the parser as a generic fallback; the metadata reader rejects that unsupported shape and preserves every previously valid caller field. Rejected saves preserve an existing file's bytes and identity. The isolated search and saved-metadata checkpoint passed 16/16 groups in 6.69 seconds; production performs no fixture scans.

Saved presentation now has a typed, bounded model for view mode, icon size, visible column order, grouping and up to four sort keys. The [public persisted format](https://learn.microsoft.com/en-us/windows/win32/search/-search-savedsearchfileformat) supports Details, Icons and Tiles, icon sizes 16–256, canonical property names and ascending/descending directions. Unsupported attributes, internal fields, unknown properties, duplicates and unrepresented child elements make an external file native-view-only; import preserves the caller's previous state instead of dropping fields. Missing supported fields retain native defaults.

The installed Windows 10 19045 handler in `Windows.Storage.Search.dll` accepts the three documented XML mode tokens. Owned files containing List, SmallIcons or Content tokens failed native binding and browsing. The public live [logical-view API](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-folderlogicalviewmode) accepts List and Content, but the probed native factory folders expose neither `IPersistFile` nor `IFolderViewSettings`. Fresh `IExplorerBrowser` hosts opened all three supported saved XML modes in Content view; XML creation alone therefore does not prove view restoration. The host explicitly applies supported presentation through native `IFolderView2` and `IColumnManager`, then reads the actual result.

All eight layouts retain their actual native mode and icon size in this application. A standard native-openable query contains the supported XML presentation fields. An additional versioned record in the app's LocalAppData `saved-search-views` directory retains the exact layout where the query format cannot express it. This is app-owned metadata, not a new Microsoft XML flag or a claim that stock Explorer reads the companion. It matches the query's canonical path, volume and 128-bit FileID, size, modification time and change time; copied, externally edited, replaced or renamed queries cannot inherit stale layouts. The companion changes only mode/icon size after importing the query's public columns/group/sort fields. It uses no query-content hashing or recursive scans.

Companions publish a flushed create-new same-directory temporary through native atomic rename. Sharing failures leave the previous record intact; malformed or foreign records are not overwritten. Query publication and companion publication are separate transactions: a companion failure after a successful query save is reported as a saved query whose view could not be saved. Older records can remain after query replacement; they are harmless unmatched app files and are not silently deleted. Closing the application and clearing its `saved-search-views` directory resets only these app-specific layouts. Headless application sessions neither resolve nor read/write the real companion directory; tests supply a fresh owned directory explicitly.

The standalone private-desktop presentation fixture passes three groups. Sixteen native saved/import/refined/re-saved/recreated cases cover all eight layouts with descending grouping and verified `System.Null` no-group, four visible columns and two sort keys. Exact native readbacks, both result FileIDs, contents, attributes and modification/change times remain equal. Invalid confirmed saves preserve the previous query; stale/copy/corrupt/foreign records and locked atomic replacement preserve outputs and existing files. Every browser uses `EBO_NOPERSISTVIEWSTATE`, creates no visible input-desktop window and leaves the clipboard sequence unchanged. This verifies app restoration through public native view APIs; shared per-folder Bags persistence remains a separately gated disposable-CI fixture.

The genuine [CI run 37235340344](https://github.com/ProtonDev-sys/windows-explorer/actions/runs/37235340344) exposed a confirmed-save DACL mismatch that the earlier default-permission local fixture did not cover. The exact equality assertion was retained. Fresh owned legacy ACL probes reproduced the cause locally: inheritance-aware setting added `SE_DACL_AUTO_INHERITED` (for example `0x8004` to `0x8404`), and high-level reading could reinterpret legacy inherited ACE flags or protection. Microsoft's [automatic inheritance contract](https://learn.microsoft.com/en-us/windows/win32/secauthz/automatic-propagation-of-inheritable-aces) describes this conversion; it is unsuitable for blindly cloning legacy permissions.

Query and companion replacement now capture the exact descriptor from the retained file handle through the documented [low-level read API](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-getkernelobjectsecurity). No `SetKernelObjectSecurity` call is used on files. [CreateFileW security attributes](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) assign that descriptor to the create-new temporary from its creation. An already auto-inherited source receives a conditional inheritance-aware conversion while the temporary is still empty. Exact DACL presence, protection/inheritance controls, ACE order, masks, flags and trustee bytes must match before query or companion data is written. Any changed-parent mismatch refuses the operation. Original and staged permissions are checked again before publication, so a concurrent ACL change fails with the existing file intact. No privilege is enabled, and the original file's permissions are never modified.

The focused `/W4` checkpoint on 2026-10-04 passed in 0.40 seconds. Six deliberately different owned native profiles cover legacy inherited ACEs, legacy explicit unprotected permissions, protected permissions, modern inherited permissions, modern protected permissions and an explicit data-write deny. Each performs real confirmed query replacement, exact independent SDDL/control comparison, native result-identity verification, sharing-failure preservation and presentation-companion replacement/readback. Query files and source contents retain their expected identities/metadata, and no staging entries remain. The private non-input desktop and clipboard remain unchanged. Failure diagnostics expose only control bits and ACE types/flags/masks/sizes; they do not print paths, SDDL or trustee identities. The obsolete `SetFileSecurity` function is used only to construct exclusively owned legacy test descriptors, never by production. This focused result is distinct from the upcoming whole-source and genuine-CI rerun.
